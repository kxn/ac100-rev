# 控制链路严格审查（2026-11-26）

> 历史规划/审查记录；2026-11-27 的有效范围、原厂入口和整改后的行为以 [策略对照](mobility-parity-audit.md)、[功能对应](feature-parity.md) 为准。旧关联预约、可修改网络模式、ACK冷却、BLE等描述不得继续作为当前要求。

先审查代码、修复并通过模拟 AP 的状态转换测试，再部署和进行 ADB 实机测试。
审查期间保持现有 AP 和客户端配置；模拟通过不能替代实机验收。

## 必须成立的约束

1. 命令及异步 JSON 回复属于同一次 AP 会话；重连取消旧请求，不能跨会话发送。
2. 保存、传输应答、配置模型回读、无线实际可用分别记录，不以 ACK 代替后两项。
3. WLAN 槽位从预留到删除提交期间不能被其它服务重用；离线和程序重启保留删除意图。
4. 每轮同步使用同一份有效配置（包括定时结果），射频重新启用必须重建其 WLAN。
5. 关联许可只是待关联，不能覆盖另一 AP 的已确认连接；客户端 IP、统计、断开按身份和位置合并。
6. 单台 AP 的超时不能阻塞其它 AP；失败的上报订阅必须重试。
7. 清理旧配置不依赖新配置的安全特性能力；能力不支持必须显式报错，不能静默省略实现。

## 审查发现

| 问题 | 后果 | 验证要求 |
| --- | --- | --- |
| JSON 请求登记旧会话后按 AP ID 再查找发送会话 | 重连时跨会话、超时或误发 | 会话替换、排队请求及等待异步回复时断开测试 |
| DELETE WLAN ACK 后立即释放槽位，早于 0x41 提交 | 旧服务仍在 AP 上时复用槽位 | 模拟延迟提交、丢失 ACK、重启恢复、重复删除 |
| 配置循环读取实时射频配置、定时重复计算 | 同一批次混入不同版本 | 固定快照，连续修改及跨定时时刻测试 |
| 射频关闭再开启只恢复射频，没有重建 WLAN | 模型显示开启，但客户端搜不到 5 GHz | 模拟 AP 清除 VAP；随后 ADB 实机验证 |
| 关联请求覆盖已连接记录、旧位置信息合并不严 | 错误显示客户端位置及连接状态 | 两 AP、双频、迟到事件、IPv4/IPv6、AC 重启恢复 |
| 上报订阅失败也记作完成 | 不再重试，界面长期没有状态 | 一次失败后恢复测试 |
| 原生 JSON 缺少 error_code 被当成功，探测超时直接退回其它写法 | 假成功、网络抖动导致错误配置路径 | 严格响应格式及传输失败测试 |

## 本轮修复与验证

- 请求和异步 JSON 固定到同一会话；DTLS 在加密锁内检查握手代次。断开立即取消正在执行和排队的请求。
- 配置响应要求匹配类型、序号和唯一有效 Result Code。缺失/重复/损坏的结果不算成功。
- WLAN 预留和所有权迁移到单个原子状态文件；DELETE ACK 只登记待删除，整批提交 ACK 后至少等待 12 秒才释放。重启重新发送未完成删除；不按定时回调直接释放。
- 每台 AP 有独立同步工作，每批使用深拷贝和一次定时计算。RF 任意变更都会使 WLAN 重新同步；关闭时保留槽位，开启时重建。
- 容量/能力在写入前检查。尚未发送的受阻配置不阻塞其它服务删除；已经部分发送的失败必须修复后再提交。
- 传统高级射频失败时恢复启用并提交恢复标记，再重建 WLAN；错误仍显示并重试。
- 订阅失败重试。原生模型必须返回明确成功；传输超时不能误判不支持然后切换写法。原生射频枚举只用于已核对的型号/硬件，其它型号保留独立 CAPWAP 实现。
- 关联许可检查已管理服务、AP/射频绑定、启用/定时；旧认证 0x01/0x13、旧关联 0x02/0x04 和新关联 0x8a/0x8b 都覆盖。
- 修正旧认证/关联编解码器：原字段实际为回填长度，不能当 VLAN；新增固定字节测试。
- 待关联与已确认位置分离；统计可确认新位置，迟到的旧位置断开不覆盖新连接。IPv6 不覆盖 IPv4，新连接不继承已断开连接的流量数据；过期状态显示待确认。
- 界面把原生回读标为“配置回读一致”，与空口可用区分；显示受阻和失败后恢复状态。

模拟 AP 经真实 UDP 验证：延迟提交、提交丢包、槽位保留/恢复、满额时删除与新增、丢 ACK 重试、RF 启停清空 VAP、配置失败恢复、两 AP 中一台不回应。另有会话替换、错误 ACK、异步回复中断、关联策略和客户端位置测试。

Go 全量测试、相关包 race、vet，以及 Linux arm64 / Windows amd64 纯 Go 编译通过。当前资源矩阵的界面测试覆盖两种能力集、五个页面、七次表单提交，无 JS 错误。

本轮代码审查已完成，进入 ADB 实机回归。提交 ACK 与等待窗口仍是协议层证据，真实 WLAN 的广播/可连接、引导及离线自管理另外验收；其他型号、多 AP 漫游和所有保留功能的完整对齐不能据此宣称全部完成。
