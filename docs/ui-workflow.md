# 管理界面按使用流程重组

问题：旧导航按实现模块平铺，AP列表与配置重复，射频页先展示优化规则，所有页面重复总览卡片。用户难以判断配置对象、入口与生效范围。

本轮只调整界面组织及交互，不改变原固件AP参数、能力判断、下发字段或漫游/均衡/RRM策略。

- 总览只负责全网状态与下一步入口，不承担高级配置；全网统计卡片仅在总览出现。
- AP管理统一包含AP列表、分组、模板、全局默认、Mesh；单AP设置从该设备进入，并明确继承来源。
- 无线服务先建立SSID、安全和AP/频段绑定；VLAN池、组播列表放在同一功能下的独立次级页。
- 射频设置默认展示每台AP的信道/带宽/功率与设置入口；速率表、EDCA各有次级页，不占据基本射频页。
- 无线优化分为无缝漫游、负载均衡、双频优选、自动射频优化，明确它们各自的作用范围。
- 客户端、运行记录负责查询；AP防护、固件升级归入维护；接口、程序容量、备份恢复归入程序设置。
- 导航、页签、面包屑使用同一份路由定义；常用配置、状态、维护不再混排。

验证（2026-11-27）：

- Playwright 使用实际 AP 能力和完整能力两组夹具，各覆盖 23 个页面，共提交 54 次表单，浏览器脚本错误为 0。写请求全部拦截，不对实验 AP 修改配置。
- 核对原有字段、表单名称和操作入口，无配置字段被删除；移除旧管理页内的重复导航，改由统一路由承接。
- 检查分组专属无线服务的应用范围显示、频段位图的精确提交、筛选控件在轮询时保持焦点、设备详情展开状态保持。
- Go 全量测试与 go vet 通过；双向索引检查通过；47 项行为契约对应的 128 个测试执行通过。这些检查不构成所有固件行为等价的证明。
- 桌面与移动布局已检查；无线名称与密码合并为第一步，默认双频选择保留原 0x7f7f 位图，可展开编辑全部 16 个频段序号。
- 射频表使用设备资源上报的 dBm 功率值，不再把 AP 统计中的独立功率刻度误标成 dBm；协议解析和配置下发不变。

预览仍使用实验环境的只读代理地址；只有读取请求会传给运行中的控制器。
