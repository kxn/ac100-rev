# V4 管理界面组织

正式界面采用用户确认的 V4 mock：蓝灰页头、左侧两级菜单、正文页签、分节表单和表格内编辑。品牌只使用“AC / 无线控制器”，不使用原厂标志、图片或前端库。所有页面继续调用独立 Go 程序的现有 API。

菜单和页面归属集中定义在 `uacgo/admin/assets/navigation.js`，面包屑、选中状态和页签使用同一份定义。

| 一级菜单 | 二级菜单 |
| --- | --- |
| 运行状态 | 客户端状态、AP状态 |
| AP管理 | AP设置、AP升级、负载均衡、智能漫游、无线网络模式、组播管理 |
| 射频管理 | 射频设置、速率设置、频谱导航 |
| 无线管理 | 无线服务 |
| 易展设备管理 | 拓扑结构、设备列表、客户端列表、高级设置 |
| 安全管理 | 广播风暴抑制、DHCP防护、ARP/ND防护 |

接口、程序容量和备份恢复从页头“程序设置”进入。原有 AP 模板、全局默认、无线运行记录、EDCA 和 VLAN 池保留在相关页面的次级页签中。`#overview`、`#management` 旧书签分别转至 AP 状态和 AP 设置。

组织依据为 V4 1.4.3 的 `frame/advanced.htm`、中文菜单定义，以及 `apmng_set.htm`、`apmng_roaming.htm`、`apmng_roaming_wireless_mode.htm`、`apmng_rdmngr.htm`、`apmng_rrm.htm`、`apmng_wserv.htm` 等原页面。这里重建页面结构，不引入原厂页面运行依赖。

AP 设置按全局设置、AP 分组、AP 列表排列。单 AP、无线服务和射频编辑在对应表格之前展开；分组、模板和设备操作使用居中对话框。统一的编辑器生命周期处理两种呈现方式，保存、取消和导航都清理同一个编辑状态。保存结果只关闭发起保存的编辑器，过期加载请求不再打开界面；轮询继续更新数据，但不替换正在编辑或等待保存的表单。

无线服务依次展示启用、SSID、编码、描述、隔离、广播、安全、密钥和带宽控制，再展示默认频段和 VLAN。逐台 AP 绑定、精确频段位图、组播和无线定时放在对应折叠区；列表提供“绑定AP”入口。频段预设保留原 16 位位图，不以两个频段开关压缩多射频配置。

智能漫游直接展示 11k/v/r、2.4G/5G 触发条件、信号和速率门限、踢除、检查间隔、差值及回连限制。取消前一版温和／标准／积极预设。速率门限按 V4 页面标注为百分比。无线网络模式单独配置；漫游与客户端调度、射频优化仍各自选择 V4/V6 策略，不改变 Go 中的固件策略算法。

射频设置继续使用实际 AP 能力约束模式、带宽、信道、功率和高级参数。射频调优使用完整的候选信道、功率和计划表单；定时优化开关同时控制规则及其时间计划，不再要求用户重复打开两个开关。完整时间计划支持每周多个时段及生效日期范围。AP 全局定点重启使用日期、时间两项；复杂既有计划使用高级编辑器保留。

DHCP 与 ARP/ND 分页编辑同一个防护规则的对应参数，保存时保留另一类参数及引用。共用的 AP 应用范围在编辑器中明确说明，删除确认明确指向整条规则。组播侦听／查询与无线服务编辑使用同一份服务配置，并按目标 AP 能力显示可用参数。

AP 详情包含 AP 信息、射频信息、能力与调试、原始上报四个页签。新增通用能力位、子能力、功能解析、射频能力来源／约束，以及配置同步状态；内容来自实际 API。复制数据使用能力字段白名单，不导出账号、密钥、PMK 或整份遥测。缺失信息显示未上报。页签和展开状态在轮询时保持。

认证、RADIUS、Portal、云管理、AC 主机系统管理和 AP 蓝牙不在菜单中。mock 中仅用于示意、但没有后端配置入口的开关不进入正式表单，例如 AP 自动接入开关（V4 原页面同样隐藏 `auto_firm`）、全局无线服务默认开关和程序内 DHCP 启停；不展示无法保存的开关。现有 AP 接入、服务自动绑定及命令行可选 DHCP 行为保持原有实现。

验证（2026-11-27）：

- 浏览器分别使用已记录 AP 能力和完整能力夹具，各检查 33 个页面，共核对 71 次操作请求；写请求全部拦截，只检查 UI 请求及保存字段，不向 AP 下发命令。
- 覆盖 AP 参数／全局计划／分组／模板、无线服务及绑定位图、射频依赖、漫游／均衡／网络模式／频谱导航、RRM／速率／组播、防护、客户端改名、Mesh、EDCA／VLAN 池／容量、升级、配置复制／替换、名称导入和备份恢复。
- 检查保存失败后的错误与输入保留、轮询中的未保存表单与详情页签保留，以及 1440／1024／390 像素下的布局。长表格在自身容器内滚动。
- 提交前复查补充：清空高级重启日期范围、RRM保存／执行分别失败后的普通重试、回车只保存、保存成功后执行失败时的规则ID保留、旧保存响应与旧射频加载请求不干扰新编辑器。上述分支均有浏览器回归检查。
- `go test ./...`、`go vet ./...`、JavaScript 语法和双向索引检查通过；Linux amd64 / arm64 静态构建通过。本次是界面与 API 交互验证，不构成新增 AP 硬件或固件策略的等价性证明。

可选浏览器检查使用本机 Playwright 环境。`tools/check_admin_ui.py` 默认只读获取 `127.0.0.1:8090/api/` 的初始快照；可用 `AC100_UI_API` 指向隔离控制器，或设置 `AC100_UI_FIXTURE=.local/ac100/ui-check/api-fixture.json` 完全离线重放。所有浏览器写请求都由测试夹具拦截。
