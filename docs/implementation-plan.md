# Go 控制器的产品范围与实机验收

目标是独立的 Go 程序，接管真实 TP-Link AP 并提供自己的中文 Web 管理界面。
原厂 QEMU 仅用于取得基准报文与行为，不作为产品运行依赖。保留纯 Go / CGO_ENABLED=0。

功能与验证不能按“存在结构体/测试通过”记完成。当前逐项核查见
[feature-parity.md](feature-parity.md)，原厂 23 个 AP 控制器、52 个页面分块的可追溯索引见
[original-feature-inventory.json](original-feature-inventory.json)。当前 AC 验收范围和自动回归入口见
[ac-acceptance.md](ac-acceptance.md)。其它型号的硬件行为未逐项实测，不直接等同于 AC 功能未实现。

## 优先顺序

1. **真实 AP 接入与管理**：选定物理接口，广播发现、DTLS、Join/Configure/RUN、心跳、离线与重连；
   多 AP 独立会话和身份持久化；AP 列表、详情、名称、位置、LED 与明确区分的重启操作。
2. **无线服务管理**：SSID、启用/停用、广播、WPA2-PSK/AES、绑定 AP/频段；保存配置、下发、ACK、状态回读；
   程序与 AP 重启后配置一致。界面区分“已保存”“设备已应答”和“已回读生效”。
3. **射频管理**：每台 AP、每个射频的启用状态、信道、带宽与功率，按设备能力约束输入；
   不能用同一套固定值覆盖不同型号。变更前后对照原厂报文和 AP 状态。
4. **无线运行状态**：AP 在线/离线、射频、SSID；客户端所在 AP/频段/SSID、连接/离线、信号与速率等
   实际上报的字段。缺失字段显示未上报，不用占位数字冒充实测值。
5. **基础闭环稳定性**：多 AP 并发、请求重传、乱序/重复、错误 ACK、重连、配置恢复、客户端上下线；
   对照原厂控制器在相同 AP 型号上的行为。Web 已接入上述真实数据与操作，不是独立演示页面。
6. **多 AP 漫游**：在以上链路稳定后完成能力判断、802.11k/v/r 和漫游策略；
   AC 的候选、命令、上报确认、失败恢复用多模拟 AP 验证；第二台 AP 用于后续实际互通记录。
7. **选择性 DHCP**：独立 Go DHCP 功能只对原厂认定的 TP-Link AP 作响应；
   普通终端请求（包括请求其它服务器的 Request）必须保持静默，不发 Offer/ACK/NAK。
   无法识别的请求默认忽略；不依靠厂商 MAC OUI 判断 AP。Option 60、原厂 for-tplink-only
   分支和实际请求需三方核对。Go 选择性 DHCP 已实现并完成模拟 UDP 与实体 AP 冷启动 DORA；
   dnsmasq 只承担专用 USB 实验终端网络，不能作为产品选择性 DHCP 的证据。

## 保留边界

AP 执行的 DHCP/ARP/ND 防护、广播抑制以及由 AC 下发的 AP 配置属于产品。
AC Linux 自身的 DHCP/DNS/NAT、ARP/防火墙、路由及管理 VLAN 不属于产品；
实验用 dnsmasq/NAT/VLAN 接口放在独立工具中。可选的 TP-Link AP 专用 Go DHCP 是用户明确要求的例外。

## 明确不做

系统认证状态；网络运维整个类别；认证管理整个类别；云管理；主机级系统管理；
主机网络设置、管理 VLAN 及主机 CPU/内存/磁盘监控。保留程序的接口选择和必要的自身配置。

## AC 验收与实机边界

每项功能按“需求 → 原厂 UI/Lua 字段 → V6 二进制函数 → 明文 CAPWAP → Go 实现 → AP ACK/回读”记录。
测试通过、UDP 发出成功或 SQLite 已写入，均不能单独证明 AP 已应用设置；状态必须准确区分保存、应答和回报确认。
基础交付需要 Go 程序单独保持 AP 在线、实际无线配置可用、客户端能连接并在界面看到状态。
AC 的完整配置、协议、状态和持久化以模拟及 API/UI 回归验收。多 AP 实际切换和硬件行为另记兼容性，
不再要求逐项 AP 空口/吞吐测试作为 AC 功能完成门槛，也不把模拟结果写成真实硬件成功。

## 已确认的首要差异

2026-11-26 的 TL-7AP5100HC-PoE/DC ClientHello 是 DTLS 1.0（feff），提供
0039/0033/0035/002f/0005/0004/000a；原厂选择 RSA/AES-256-CBC/SHA（0035）。
当前 Pion v2 后端没有这一 RSA 密钥交换路径，所以仅启用原有 Pion 组件不能完成真实接入。
已新增独立兼容后端并用真实 AP 接入验证；功能进度和未完成的验收见
[Go 实机进度](go-live-status.md)。Pion v2 测试继续单独保留。
