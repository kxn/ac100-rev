# UAC/Web 双向复核与根因整改（2026-11-27）

范围遵循用户确认：独立 Go 控制器及 Web；AP 管理、无线服务、射频、客户端、Mesh、防护、调度与漫游保留，AC 主机系统、RADIUS/Portal、蓝牙等排除。Go 程序容量与可编辑初始配置独立制定；AP 协议和策略按提供的 V6 固件核对。

## 整改计划

1. 统一 AP 会话容量：删除旧 MaxSessions 字段和无界队列回退，直接接入与 Mesh 接入在同一锁内按同一实时资源配置登记；保留重连替换语义。
2. 统一配置边界：启动和写入共用完整的结构、引用和参数校验；设备能力校验独立；资源反序列化和部分编辑分离，删除 JSON 往返验证和测试专用空引擎兜底；资源仅变更时应用。
3. 统一客户端事实：只保留携带会话代次和完整性检查的无线快照入口，删除第二条 IP 修补路径；连接状态不再由页面自创的六分钟静默阈值修改。
4. 将文件级双向索引补为可执行行为合同：原固件函数/地址/哈希或 Lua 入口对应 Go 实现符号和实际执行的测试；Go 自有行为明确分类。复核策略触发、计算、边界向量，不运行原固件作黑盒算法推导。
5. 清理以自身实现互相证明、重复检查和源码字符串限制为核心的测试；保留不可信协议输入、会话隔离、容量和持久化边界的有效验证。全量测试、race、vet、构建、界面检查后记录实际结果与证据范围。

## 验证记录

[行为合同](uac-web-behavior-contracts.json)覆盖 18 条功能链路、46 项合同、67 个 Go 实现符号及 126 个实际执行的指定测试。129 个已取证 UAC 函数全部归类；162 项去重源码引用包括 UAC 函数、原 Lua 入口、RRM 库和 DHCP 原程序锚点。RRM/DHCP 锚点不是函数边界指纹，其完整二进制另有 SHA-256 固定。活动源链中的辅助函数引用不表示逐指令复制了平台存储实现。

`python3 tools/check_behavior_contracts.py --verify-firmware --run-tests` 检查源码标识、Go 函数声明、Go 自身测试发现和实际 pass 事件；用例丢失、跳过或仅出现“没有可运行测试”不能算通过。`check_parity_map.py` 继续负责原 23 个模块及 186 个 Go 文件的双向归类。固件原函数指纹、原编译表和 2029 条 OUI 重建核验通过；均衡/漫游/RRM 的判断没有使用原程序黑盒或 AP/客户端试验推导。

以下最终检查均通过：全量无缓存 Go 测试、vet、race，Linux amd64/arm64 与 Windows amd64 纯 Go 构建，以及两套能力×11 页面、50 次表单的 UI 回归。测试范围是具名分支与控制器链路，不等于所有参数/型号的形式化等价证明。
