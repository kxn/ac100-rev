# 首次接入、型号默认模板与重连

原厂 V4/V6 的 `apmngr_ap_add` 调用 `apmngr_db_template_get(model_id)`。匹配键是型号 ID，不是 AP MAC、名称相似度、测试型号或硬件版本字符串。模板来自 `ApTemplate_table`；`ApEntryCfg_table` 是设备实例，不能从任意同型号设备挑一份配置充当型号默认值。

| 路径 | 原厂依据 | Go 行为 |
| --- | --- | --- |
| 首次 Join | V4 `555d80/52cf4c`；V6 `60b040/5d59e8` | Join 成功应答之前保存设备配置；显式型号默认模板复制一次，保存到独立 AP 参数 |
| 型号查模板 | V4 `540b20`；V6 `5c6030` | `apply_on_join=true` 且 `model_id` 精确匹配；同一型号只允许一个默认模板 |
| 没有匹配模板 | `apmngr_ap_add` 的 APDB 默认路径 | 创建独立 AP 配置，不借用另一台 AP；后续新增模板不追溯应用 |
| 已有设备重连 | Join 先按 MAC 找已有记录 | 持久化设备记录及已导入 AP 配置均视为已有设备，不重新复制模板 |
| 型号 ID 为 0 | Join 按已有记录，或按型号名与硬件查 APDB | 优先恢复持久化型号，首次设备按精确名称和硬件查库；不替换当前上报能力树 |
| 模板参数初始化 | `apmngr_ap_add` 的参数块复制与保留字段 | 型号模板复制不含安装位置；FIT/FAT 按键、Mesh、区域与当前射频角色不从另一台设备套用 |
| 射频模板 | `rdmngr_api_for_apmngr_inherit` 与 `rdmngr_db_rd_inherit` | 保留模板射频行，按新 AP 的射频与能力投影后保存，不复制 AP 运行统计 |
| 分组 | 新建参数中的模板分组与 Join 的 `switch_group_handle` | 初始分组后执行 IP 规则，时机在 Join；封装 Mesh 子设备跳过直接接入的 IP 规则 |
| Mesh 子设备 | 原厂封装 Join | 与直接接入共用登记、初始化及失败处理，不遗漏设备持久化 |
| 登记失败 | 原厂创建失败不进入成功接入 | 初始化或设备数据库失败时不返回成功 Join 应答，记录 `ap.registration_failed` |

`initial_template_id` 仅记载首次参数来源，不是动态继承链接。管理界面原有的“应用模板”仍是显式关联；导入的单台 AP 快照仍可用于该设备，但默认不会自动应用到其他设备。页面将两种用途分别标为“首次登记时复制”和“仅手动关联”。型号 ID 同时在 AP 能力数据中可见。

备份转换单独读取 `ApTemplate_table` 和归属该模板的 `rdmngrTable` 行；不会把单台 AP 行提升为型号默认模板。本次现场备份的原厂模板表为空，因此不会凭空生成型号默认值。任何新默认模板都需要来自原厂模板或用户明确配置。

原厂的能力协商由发现、APDB 与 Join 多个阶段组成。Go 优先使用 AP 当前上报的能力，缺失时查完整原厂基础库/已导入协商库；配置了型号库而仍无可用射频能力时，不能假装已完成兼容接入。未报告或无法解析的功能不会靠借用其他型号填补。该处理不等于重新实现原厂所有 APDB 网络协商分支。

源码函数的版本、完整字节哈希、Go 入口及回归向量列在 `uac-web-behavior-contracts.json` 的 `ap-first-registration`，并由双向索引检查。模拟 AP 验证入口和持久化边界；它不作为原厂策略来源。现场已经恢复上线不能证明此前一次 Join 停滞的根因已修复。

## 重传与恢复状态的门禁纠错

旧Go代码及旧测试错误地把Join完成阶段的重复Join丢弃。两版原函数的末尾分支实际上允许它；Configure同样允许重复Config。现按完整条件表达式核对并修正：

| 状态 | 两版原函数允许的消息类型 |
| --- | --- |
| JOIN_WAIT | 0、3 |
| JOIN_FINISH | 3、5、15 |
| CONFIGURE | 5、11 |
| IMAGE_DATA | 13、15、16 |
| DATA_CHECK | 9、11、13 |

重复Join/Config重发已保存的对应应答，不再创建或初始化AP。DATA_CHECK收到Echo/事件后恢复RUN，重复Change State只重发；失败或超时清理会话。IMAGE_DATA的允许集合、Echo续期、失败/超时及完成转RESET也按原函数补齐。该状态机合同不声称旧CAPWAP镜像传输组件已变成另一套可用升级通道；产品升级入口仍由现有升级组件负责。

旧测试对错误丢弃的期待已改成对线上应答的检查，另有按两版源码列出的完整门禁集合测试。此前现场一次Join停滞没有观察到AP再次发送Join，因此不能把本次重传修复直接认定为那次故障的根因。
